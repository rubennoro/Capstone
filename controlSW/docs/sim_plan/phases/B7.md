# B7: rig stream sender + rig replay + sim-rig-fake profile (Track B, wave W7)

## Goal

The custom sensor rig's half of the wireless path, on the same receiver as the iPhone:
- On the rig Jetson, `sensor-rig stream-send` reads `RigFrameSource` (virtual-iPhone images at 960×720, true capture stamps) and sends v2 packets over Wi-Fi to the policy host.
- In sim, `rig_replay_sender` runs **the same sender code** on a recorded or simulated raw rig episode (mock backend).
- The `sim-rig-fake` profile runs the full stack end to end, like `sim-iphone-fake`.

## RigStreamSender (`sensor_rig/stream/sender.py`)

```python
class RigStreamSender:
    def __init__(self, rig, host: str, port: int, *, fps_hz: float = 30.0, jpeg_quality: int = 90, backend: str = "argus",
                 backend_opts: dict | None = None, pairing: dict | None = None, max_queue: int = 4,
                 drop_policy: str = "drop_oldest", output_size=(960, 720), clock: str = "sender_monotonic",
                 transport=None)          # transport: object with send_packet(dict, size)/answer_ping; default = socketio client
    def run(self, duration_s: float | None = None) -> dict    # returns stats
    def stop(self)
```

- Uses `RigFrameSource(rig, output_sizes={"main": (960, 720), "ultrawide": (960, 720)}, backend=..., sync="live")`. The remap happens on the sensor side, so the wire carries iPhone-equivalent images.
- **Per packet:**
  - JPEG-encode both images with cv2 at the given quality;
  - v2 `make_packet(seq, main_jpeg, uw_jpeg, t_main_ns=packet.t_capture_ns["main"], t_uw_ns=...)` in the **sender's CLOCK_MONOTONIC**, the rig's real capture times;
  - `hello` once after connect with the virtual camera K at 960×720;
  - answer `clock_ping` with `time.monotonic_ns()` (t1, t2).
- **Queue:** a bounded queue (`max_queue`) between capture and send with drop-oldest, so the rig has real backpressure. Unlike the app, it never builds latency. Count drops.
- **Socket transport:** python-socketio client, websocket. sensor_rig must not import franka_deploy, so the client code is small and local, reusing `protocol.py`.
- **CLI:** `sensor-rig stream-send --rig R --host H [--port 5555] [--fps 30] [--jpeg-quality 90] [--backend argus|mock] [--episode DIR] [--duration S]`.

## rig_replay_sender (franka_deploy)

`python -m franka_deploy.stream.rig_replay_sender --episode <raw rig episode dir> --host 127.0.0.1 --port 5555 [--link run/link/wifi_good_skew.yaml] [--truth T.jsonl] [--ready-file F] [--loop]`

- Builds `RigStreamSender(backend="mock", backend_opts={"episode_dir": …, "loop": …, "realtime": True})`, with a transport that routes through B4's `LinkEmulator`. This gives the clock offset and drift on the stamps and on ping answers (sender clock = `link.sender_clock_ns()`), plus delay, jitter and stalls.
- **Truth lines:** `{seq, stream, t_true}` in host monotonic (the mock camera's replay time).
- **Ready file:** `{start_now_ns, first_tick_ns, fps, protocol: "v2", episode, K_main, K_uw}`.
- **Episode source:**
  - a raw rig episode generated by `simulate_raw_from_iphone(<firstreal iPhone episode>, SIM_RIG_PATH, <scratch>)`;
  - the test fixture makes one from one short firstreal demo if none exists (cache it under scratch);
  - `run/sim/rig_raw_replay.yaml` names how to pick or generate it.
