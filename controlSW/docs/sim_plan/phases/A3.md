## Pipeline

**Per demo:**
1. TCP poses in the ARKit world → z-up (`frames`).
2. Grasp index from `metrics.phases(width, height_up, t)`.
3. Grasp TCP point.
4. 60 Hz time base.

**Placement:**
- `anchor_placement` puts each demo's grasp TCP at `(gx, gy, table_top + scene.grasp_tcp_height_m)` with yaw ψ; gravity is kept.
- base_T_tcp(t) → base_T_EE(t) = base_T_tcp · inv(EE_T_TCP) (the flange frame while `desk_end_effector: none`).

**IK:** frame 0 by multistart (seeds: home q + random); afterwards warm-started. A frame fails if the residual is > 1 mm or > 0.5°.

**Metrics per (demo, placement):**
- reach fraction, first failing index;
- minimum joint margin (rad and % of range) and the joint;
- minimum manipulability;
- peak |dq|/dq_max and |ddq|/ddq_max (Savitzky–Golay smoothing at 60 Hz, window from stage1.yaml);
- jerk ratio (reported, flagged noisy);
- collision count and **minimum distance for: tooling (housing/cradle) ↔ links 1–7, arm ↔ table, self**;
- safety: box violations, cone angle > `scene.workspace.cone_max_deg`;
- **leaky-bucket clamps:** feed the EE path at 200 Hz through the real `SafetyFilter(SafetyConfig.from_dict(<bridge safety from station.bridge_fragment()>))` and report clamp fraction, maximum backlog (m), and slowdown = time to finish the path at `criteria.limits.v_max_m_s` ÷ demo duration;
- Cartesian TCP speed p99 / max against the datasheet;
- width: gap = (w − b)/a, fraction outside [0, 0.080], p99 mapped width against the stroke.

**Search:**
- **Coarse:** 10 Hz, grid from stage1.yaml (default gx 0.30–0.70 × gy −0.30–0.30 in 7×7, yaw every 45°), multiprocessing `--jobs`.
- **Fine:** 60 Hz on the top 5.
- **Score**, in order: (a) the number of demos fully feasible (reach 100 %, margin ≥ `criteria.stage1.joint_margin_deg_min`, 0 collisions, tooling clearance ≥ 0.010 m); (b) the worst joint margin; (c) the clamp fraction.

**Design sweep:**
- Run the whole search for each combination of: `--robots panda,fr3`, `--finger-extensions 0.0,0.05,0.10`, `--camera-sides +y,-y`.
- Use `--set tooling.finger_adapter.extension_m=…` and `--set tooling.tcp_x_along_hand=…` through the station `sets`.
- Each combination rebuilds the model.
- Sensitivity: rerun the best combination with `scene.grasp_tcp_height_m` ±0.01.

**Outputs** (a directory outside the repo, e.g. `$SCRATCH/stage1/`):
- `stage1.json` per combination: placements tried with scores; the recommendation `{grid point, yaw, base_T_world per demo}`; per-demo metrics at the recommendation; `start_q` and the start TCP pose per demo; the recommended home TCP pose and q (median of the demo start poses relative to the grasp point, solved by IK); the station fingerprint; schema `stage1/v1`.
- `design_summary.json` + `summary.txt`: one table over robot × extension × side with the number of feasible demos, worst clearance, worst joint margin, clamp fraction and slowdown, plus a recommended design.

## Tests (`tests/test_stage1.py`, RE; must take < 60 s total)

1. A synthetic straight-line demo (built in `tmp_path` as an npz or a tiny zarr, 60 Hz, slow) gives 100 % reach and 0 clamps.
2. A synthetic over-speed segment (0.6 m/s for 0.5 s) gives clamp fraction > 0 and slowdown > 1, matching a hand computation from v_max within 10 %.
3. A demo placed out of reach is flagged with its first failing index.
4. Determinism: the same `stage1.json` (excluding timestamps) twice.
5. `sets` for extension and side reach the model (F_T_TCP z changes by the extension).
6. Real-data smoke: `--quick --demos 0,1 --robots panda` on `$ZARR` runs and produces the schema (skip if `$ZARR` is missing).

## Run (the executor runs these and reports)

The full sweep in the background: 45 demos × {panda, fr3} × {0, 0.05, 0.10} × {+y, −y} with `--jobs 4`. Report the wall time. If it would exceed ~60 min, reduce the coarse grid or use 5 Hz coarse and say so.

## Acceptance checklist

1. Tests pass (< 60 s).
2. The full sweep has run; `design_summary.json` + `summary.txt` exist; the table is in the final report.
3. The clamp fraction at v_max 0.25 is consistent with the dataset fact that ~7 % of demo time exceeds 0.25 m/s (explain any difference).
4. The recommended design (robot-agnostic if possible), placement and home are stated with their gating numbers.
5. Only Track A files changed (plus stage1.yaml values).
