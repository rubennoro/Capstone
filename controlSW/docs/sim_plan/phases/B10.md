## wireless-latency (`tools/wireless_latency.py`)

```
python -m franka_deploy wireless-latency measure --config deploy.yaml --profile real-iphone|real-rig [--set k=v] \
    [--duration-s 60] [--display-hz 60] [--fullscreen] --out DIR
python -m franka_deploy wireless-latency analyze --frames DIR/frames.jsonl --out DIR
python -m franka_deploy wireless-latency synth --protocol v1|v2 --latency-s 0.08 --out DIR   # self-test, no device
```

- **One process, one clock.** A window shows a QR of `"{t_mono_ns} {counter}"`, redrawn at `--display-hz`, on the policy host's own screen. The phone (or rig) films it.
- **Frames come from the B5 receiver run in-process with the station's `camera_config`.** Subclass `WirelessCamera` and hook `_on_v1` / `_on_packet` to get (stream, image, t_arrival, sender stamp); do not edit the receiver. Decode with `cv2.QRCodeDetector` on a downscaled grey copy, off the socket thread.
- **Per stream:**
  - v1: `arrival − t_qr`, which is what `clock.latency_s` must equal;
  - v2: `mapped_stamp − t_qr` → `residual_latency_s`.
  - Report n, decode rate, p05/p50/p95/max, and the drift over the run (a linear fit).
- **Bias:** the QR time is the draw time, so the result over-estimates by the display lag (≤ 1 refresh + panel, ~10–25 ms at 60 Hz). Print it as a stated bias with the display Hz, and recommend a ≥ 120 Hz screen.
- **Output:** `latency.json`, `frames.jsonl` (no images), plus a snippet:
  - v1: `sensor.clock.latency_s.main=<p50>`, `...ultrawide=<p50>`;
  - v2: `sensor.clock.residual_latency_s.*`.
  - Also the task's `sensor.task.camera_latency_s` suggestion with the reasoning: the task value is the pause wait, not a stamp correction (`station.camera_config` docstring).
- **Pass numbers** (docs): decode rate ≥ 0.8; p95 − p50 ≤ 30 ms (v1) / 5 ms (v2) (= `criteria.stage2.cam_stamp_err_ms_p95_max`); the latency is stable over 60 s within 5 ms.

## stream-intrinsics (`fdcal/stream_intrinsics.py`)

```
python -m franka_deploy fdcal capture stream --out DIR --n 30 [--camera tcp://localhost:16702] [--stream main|ultrawide|both]
python -m franka_deploy fdcal stream-intrinsics --data DIR --config deploy.yaml --profile P [--squares-x 9 --squares-y 7 \
    --square-m 0.03 --marker-m 0.022 --dict DICT_5X5_100] [--distortion none|k1k2] --out DIR
```

- **Board and pose detection:** reuse `handeye.make_board` / `board_pose_from_image` conventions.
- **Fit:** `cv2.calibrateCamera` (or the ChArUco variant) per stream at 960×720, with `--distortion none` by default (the iPhone streams are expected rectified) and `k1k2` to test that.
- **Compare** with:
  - the station `streams.<s>.K`;
  - both `training_intrinsics_variants` scaled to 960×720 with the half-pixel rule (`iphone_replay_sender.scale_K`; UW variant 2 has no `uw_c_px`: compare f only).
  - Report the relative f and c differences (%), the reprojection RMS, the nearest variant and the per-image coverage of the frame (corners in each 3×3 cell).
- **Verdict:** `match` if |Δf| ≤ 0.5 % and |Δc| ≤ 3 px vs the station K; else a snippet for `sensor.streams.<s>.K`. Note that the policy was trained at the training K: a mismatch is a finding, not something the snippet fixes.
- The ChArUco board is already on the hardware-day list (PURCHASING §3).

## Franka Hand width map (`fdcal capture width`, `fdcal width`)

- **`capture width --hand-endpoint E --gaps 0.0:0.08:0.005`:** for each gap, `hand_cmd move` (I-HAND, `BridgeClient`), wait for `move_ok` or 3 s, grab a UW frame, log `hand_state.gap_m`. The servo path (`--controller-config --positions`) is unchanged.
- **`width --linear`:** raw tag separation from `raw_width`; **training width = raw − `tooling.width_map.train_closed_m`** (the training data's closed value, not the sweep minimum); fit `train = a·gap + b` (least squares, residual p95).
  - Checks: monotonic; residual p95 ≤ 1 mm; coverage of the training range 0.0447–0.0844 within the 0–0.080 stroke.
  - Snippet: `tooling.width_map.a/b`.
- **Docs consequence:** after the fit, re-check that the demo hold widths (0.046–0.062) map to a gap that closes on the eraser side the demos grasp. Watch a demo video to say which side; the A5 mismatch is 38–54 mm vs 20 mm. Also re-check `hand.grasp_epsilon_inner_m` (0.05, A5) and the hysteresis thresholds `close_below 0.064` / `open_above 0.070`.
