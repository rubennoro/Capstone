- **`first_tick_ns`** = start_ns + tt[0], the same formula the send loop uses for t_target. It is additive, and the docstring documents that the replay_gt alignment uses start_now_ns.
- **`split_script`** (l.167) splits only on a comma that is followed by `<num>:`. Every script that worked before splits the same way; only JSON payloads gain.
- **Hand child** (l.700):
  - runs only for franka_hand on a non-bridge endpoint (both sides normalised);
  - uses libfranka for panda_py, else fake;
  - takes the hostname from the station `robot.fci.hostname`;

- **Age p95 ~118 ms is plausible; it shows no hidden latency.** Age is measured at the 60 Hz publish tick as `now - fm[1]`, with `fm[1] = t_arrival - clock.latency_s (0.08)`. That gives 80 ms constant + time since the 30 Hz frame arrived (0-33 ms, p95 ~31 ms) + tick jitter, about 113-118 ms. In arrival_minus_latency mode the 8 ms Wi-Fi delay never appears in age (the assumed 80 ms absorbs it). The task-side age (`now - main_ts[-1]`, the same stamp) sits on the same ~80 ms floor, well under 0.35 s.

## Findings
1. (info) launcher.py:900: sender death is non-fatal: a single HOLD plus `summary.sender_died`, and the sender is never restarted. A sim session therefore never recovers images. It does not spin either: the task retries 3 times and then holds, until q or the script ends. That is acceptable for an operator. **B8's runner must treat `sender_died` as an episode abort**, or a scripted eval idles to its timeout.
2. (low) franka_task.py:373: the guard placement after frame selection matches the spec. In the kill run, frame_select's dropped-frame check fires first, so `stale_image` stays 0. That is acceptable: same exception, same retry/hold path, and the receiver also stops publishing past `health.max_age_s` 0.3 s. The guard only covers the robotmq-retention case and is proven only by the unit test. Suggestion (not required): B7/B8 add a link-stall e2e (~0.4 s outage) that shows `stale_image > 0`.
3. (low) launcher.py:414 + deploy.yaml:84: `user_site_children: [camera, sender]` stays confined to the sim profiles. `real-iphone`/`real-rig` use their own anchor and do not inherit it, and the base/Jetson profile does not set it.
