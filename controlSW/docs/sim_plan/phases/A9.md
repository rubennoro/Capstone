## Why

Today the printed fingers are two rigid boxes (`pad_l`, `pad_r`, 20×8×30 mm) on the stock menagerie fingers, tags are
patches at fitted offsets (`TAG_Y_EXTRA_M`, `TAG_Z_FROM_PAD_M` in `franka_sim/franka_sim/model.py`), pad offset 8 mm is a
placeholder, TCP is at the pad centre. A **finger kit** (meshes + named reference frames, data only) lets the builder
place the real CAD fingers; box mode stays the default and must stay byte-identical.

## Frame chain (per finger, all frames: z = toward the fingertip, y = outward = away from the other finger)

```
hand ─(menagerie slide joint, unchanged)─▶ finger body (hand/left_finger, hand/right_finger)
     ─▶ J  jaw mount = stock finger base face: origin (0, y_c, z_base) in the finger body frame, axes = finger body axes
     ─▶ J_T_M = Trans(0, dy, L) · Rz(yaw_deg)        (L = adapter_length_m, dy = lateral_offset_m or auto, yaw default 0)
     ─▶ M  kit mount frame of the part on that side;  meshes posed by inv(kit_T_M) (kit_T_M given in kit/CAD coords)
```

- J from the vendored mesh at build time (never hardcoded): `finger_0` in the left_finger frame has its base at z = 0,
  footprint x ∈ [−10.5, 10.5] mm, y ∈ [2.5, 26.3] mm (y_c = 14.4 mm), tip z 53.9 mm, pad face y ≈ 0 at gap 0. Same code
  path for both fingers (menagerie right finger = left rotated 180° about z, so its body frame also has +y outward).
- `lateral_offset_m: auto` → dy such that the two contact (TPU) parts just touch at Franka gap 0 (min over contact-mesh
  vertices of the inner-most y, in the finger body frame, equals 0). Report the result.
- Each side's part declares `camera_face: +x | -x` (in its M frame). The builder computes, per Franka finger, the
  camera direction in that finger's frame (`dir_f`, existing logic in model.py step 3) and mounts the kit side whose
  camera_face sign matches. Kit sides are named by part (`left`/`right` = holder_left/holder_right), not by Franka finger.
- TCP (iPhUMI definition: "end of the gripper, middle of the fingers", see
  `iPhUMI/python_package/iphumi/demonstration_processing/calibration/compute_iphone15pro_calibration.py`): midpoint of the
  two `tip` points (each in its M frame, transformed to the hand frame at gap 0). The TCP origin is (0, 0, z_mid) in
  the hand frame (on the centre line); report the midpoint's dropped x/y as `tcp_residual_mm`. Axes as today (x = sgn·hand y via `tcp_x_along_hand`, z = hand z).
- Tags from the kit: centre, normal (points out of the tag face, toward the camera), up, id, size; placed as today's
  `tag_{l,r}` (white, 1 mm thick, size_m square) + `tag_{l,r}_ink` (black, 0.6·size, 0.1 mm proud) geoms. Names unchanged.

## Kit format (`finger_kit/v1`)

Directory with STL meshes, `kit.yaml`, `SOURCE.md`. `kit.yaml`:

```yaml
schema: finger_kit/v1
id: <str>
units: mm                      # mm | m: applies to every length and mesh in this file
parts:                         # name -> part
  finger:  {mesh: finger.stl, role: contact,   material: tpu, collision: hull}
  holder_left:  {mesh: finger_holder_left.stl,  role: structure, material: pla, collision: hull}   # or collision: [a_c0.stl, a_c1.stl]
  holder_right: {mesh: finger_holder_right.stl, role: structure, material: pla, collision: hull}
materials: {pla: {density_kg_m3: 1240}, tpu: {density_kg_m3: 1210}}   # or a part's mass_kg (measured) overrides density
sides:
  left:  {parts: [finger, holder_left],  kit_T_M: <4x4>, camera_face: "+x", tip: [x, y, z],
          tags: [{id: 0, centre: [..], normal: [..], up: [..], size: 16}]}
  right: {parts: [finger, holder_right], kit_T_M: <4x4>, camera_face: "-x", tip: [..], tags: [{id: 1, ...}]}
contact: {friction: [1.0, 0.005, 0.0001], solref: null, solimp: null}   # null -> model.grip_contact()
provenance: {<key>: {status: measured|derived|placeholder|decision|datasheet, source: "..."}}
```

- Every side has exactly one `role: contact` part (becomes `pad_{l|r}` for the Franka finger it is mounted on).
- A part used by both sides is placed with each side's own `kit_T_M` (the TPU finger is the same STL on both sides; if
  the right side needs the mirrored finger, the kit lists a separate mirrored STL — do NOT mirror in code).
- `SOURCE.md` table: relative path | bytes | sha256 (same format as `franka_sim/franka_sim/assets/SOURCE.md`).
- kit sha256 = sha256 over `kit.yaml` bytes + each listed file's sha256 in sorted path order (define once in
  finger_kit.py as `kit_digest(dir)`).

## Tooling keys (under `tooling.finger_adapter`)

```yaml
kit: null                            # path relative to controlSW (like robot.model.mjcf) or null = box fingers (today)
kit_sha256: null                     # required when kit is set; must equal kit_digest(kit dir)
adapter_length_m: 0.0                # L (kit mode only)
lateral_offset_m: auto               # dy: "auto" or a number (m)
adapter_yaw_deg: 0.0
adapter_section_m: [0.021, 0.024]    # placeholder block cross-section (x, y); default = stock finger footprint
```

Validator (`franka_deploy/franka_deploy/station.py`, no mujoco/numpy-heavy imports): `kit` null or a str; when set,
`kit_sha256` must be a 64-hex str; `lateral_offset_m` is "auto" or a number; `adapter_length_m` ≥ 0; every key has
provenance (the existing unit-suffix and provenance rules already apply). The kit path existence is checked by the
loader in franka_sim (the Jetson has no assets).

## Addendum (user, 2026-10-27): finger modes, kit variants, accuracy documentation

**Finger modes** (`tooling.finger_adapter.mode`; absent → `kit` if `kit` is set, else `box`, so today's files keep their
meaning):
- `stock`: the unmodified menagerie Franka fingers (stock fingertip pad collisions stay ON, no adapter, no tags, no
  printed parts). TCP = midpoint of the stock fingertip pads (`fingertip_pad_collision_1` centres, hand frame), on the
  centre line; `info["tcp_at"] = "stock_pads"`, `info["pad_length_m"]` = the stock pad's z extent. `pad_l`/`pad_r` names
  must still resolve: name the stock pad geom `fingertip_pad_collision_1` of each finger `pad_l`/`pad_r` (rename in the
  spec at build time) so scene/kinematics/campaign keep working. Images show no tags (documented: not training-equivalent
  for vision; for grasp-physics and reach comparisons).
- `box`: today's boxes, byte-identical.
- `kit`: the finger kit.

**Kit variants** (`tooling.finger_adapter.kit_variant`, default `full`): `kit.yaml` may define
`variants: {full: {left: [finger, holder_left], right: [finger, holder_right]}, finger_only: {left: [finger], right: [finger]}}`.
A variant overrides each side's `parts` list; tags belong to the side but are only placed when their carrier part is in
the variant (tags get a `on: <part>` field; a tag whose carrier is absent is skipped and reported). Without `variants`,
only `full` (= the sides' own parts) exists. finger_only = "just the printed soft fingers" on the adapter.

**Accuracy documentation** (piece A9g): `controlSW/franka_sim/docs/finger_model.md`, the justification for every
sim outcome that depends on the fingers: the frame chain with a diagram; a table of every geometric/physical number
(value, unit, status measured/derived/datasheet/placeholder, source, which stages it affects); the validation evidence
(box-equivalence tolerances, auto_dy closure, camera-check tag error with the kit vs fitted boxes, Stage 1 / 1b deltas);
known limits and their expected effect on each stage (rigid TPU, placeholder adapter, J from the menagerie mesh,
friction); how to switch modes/variants. Numbers in the doc are generated, not typed: `python -m franka_sim finger-kit
report --profile P [--set ...] --out DIR` (A9d) writes `finger_report.json` + a markdown table that the doc embeds.
