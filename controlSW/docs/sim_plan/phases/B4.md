## Protocol (`protocol.py`)

- **v1 (iPhone app):**
  - one Socket.IO server per stream port (main 5555, ultrawide 5556);
  - event `"rgb"` with a **str** payload = base64 JPEG;
  - event `"validate"` emitted every 1 s with an ack callback. The server must return a non-empty value; the reference returns "server got it!";
  - event `"depth"` (ignored);
  - no stamps, no seq.
  - Verify the exact event names, payload type, the ack/timeout semantics and the reconnect trigger from the Swift code, and write them down in the module docstring with file:line.
- **v2 (rig and sim senders):**
  - on the main port only;
  - event `"hello"` `{v:2, sender, protocol, streams, fps_hz, K}` once after connect;
  - event `"packet"` `{v:2, seq, main_jpeg: bytes, uw_jpeg: bytes, t_main_ns, t_uw_ns, clock: "sender_monotonic"|"sender_realtime", w, h}` (binary attachments);
  - server → client call `"clock_ping"` `{t0_ns}` → `{t1_ns, t2_ns}` in the client's clock.
- **Helpers:** `EVENT_*` constants; `encode_v1(jpeg_bytes) -> str`; `decode_v1(str) -> bytes`; `make_packet(...) -> dict`; `check_packet(d) -> list[str]`; `make_hello(...)`.

## LinkEmulator (`link.py`)

```python
@dataclass
class LinkConfig: latency_s=0.0; jitter_s=0.0; stall_rate_hz=0.0; stall_duration_s=(0.05, 0.25); bandwidth_mbit_s=0.0 (0 = inf)
                  clock_offset_s=0.0; clock_drift_ppm=0.0; seed=0
    @classmethod
    def from_yaml(cls, path_or_dict) -> "LinkConfig"       # run/link/*.yaml schema
def schedule(cfg, send_t: np.ndarray, sizes_bytes: np.ndarray) -> np.ndarray   # pure, deterministic deliver times
class LinkEmulator:
    def __init__(self, cfg: LinkConfig, deliver_fn: Callable[[Any], None])
    def submit(self, item, size_bytes: int, t_send: float | None = None) -> None   # non-blocking; FIFO, unbounded
    def sender_clock_ns(self) -> int        # monotonic_ns + offset + drift*(t - t0)
    def stats(self) -> dict; def close(self)
```

Rule: `deliver_t[i] = max(deliver_t[i-1], send_t[i] + latency + jitter_i, bucket_free_t + size_i/bw) + stall_i`.
- jitter is gamma-distributed with mean `jitter_s`;
- stalls are a Poisson process at `stall_rate_hz` with uniform duration, and hold back every item behind them (head-of-line);
- delivery is in order, and nothing is ever dropped.

A delivery thread calls `deliver_fn` at `deliver_t` (monotonic clock).

## StreamClient (`client.py`)

```python
class StreamClient:
    def __init__(self, host: str, ports: dict, protocol: str, link: LinkConfig | None = None,
                 truth_path: str | None = None, validate_period_s: float = 1.0)
    def connect(self, timeout_s=10.0); def close(self)
    def send_v1(self, stream: str, jpeg: bytes, t_true_capture: float, seq: int)  # one socketio.Client per stream
    def send_v2(self, main_jpeg, uw_jpeg, t_main_true: float, t_uw_true: float, seq: int)
    def stats(self) -> dict          # sent, delivered, backlog_s, reconnects, transport
```

- **websocket transport only** (`transports=["websocket"]`).
- v1 reproduces the app's validate loop: every 1 s, `call("validate")` with a 1 s timeout; reconnect only under the app's conditions.
- `clock_ping` handler (v2) answers with `link.sender_clock_ns()`.
- `t_*_true` are the true capture times in **this host's monotonic clock**. They are written to the truth file as `{seq, stream, t_true}` JSON lines.
- v2 stamps sent on the wire are in the **sender clock** (skewed by the link).
- All emits go through the LinkEmulator when one is given.

## iPhone replay sender (`iphone_replay_sender.py`)

`python -m franka_deploy.stream.iphone_replay_sender --episode <raw iPhone episode dir> --host 127.0.0.1 [--ports 5555,5556] [--protocol v1] [--fps 30] [--size 960x720] [--jpeg-quality 90] [--link run/link/wifi_good.yaml] [--truth T.jsonl] [--ready-file F] [--loop] [--start-now-ns N] [--max-s S]`

- Reads with `IphoneEpisode`.
  - Main video is 1920×1440 (60 Hz) and UW is 640×480 (about 10 Hz, from `uw_slots`). Resize both to the output size (main ×0.5; UW ×1.5) with the half-pixel convention (`cv2.resize` INTER_AREA for downscaling, INTER_LINEAR for upscaling; document the choice).
  - At `--fps 30` main sends every 2nd frame. UW is sent at its own slots, held at 30 Hz only if the app does that: check the Swift code. The app streams the multicam UW at the camera fps, while training UW came from ARKit at 10 Hz. Emulate the **app** (deployment) behaviour, and log the decision.
- **Pacing:** use the episode's own frame times, mapped to monotonic via `--start-now-ns`, or now. JPEG-encode with cv2 at the quality given.
- **Ready file** (JSON, written atomically): `{start_now_ns, fps, protocol, episode, K_main, K_uw}` with **this episode's own K** (from the episode JSON, scaled to the output size with the half-pixel convention).
- `--protocol v2` is supported too: packets carry sender-clock stamps of the true capture times.
