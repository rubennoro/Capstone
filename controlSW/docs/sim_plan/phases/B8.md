# B8: eval runner, criteria, Stage 1 wrapper, Stage 2a (offline predictions) and Stage 2b (live open loop) (Track B, wave W8)

## Goal

`python -m franka_sim eval` is the single entry point that runs evaluation stages for **any policy** on **either sensor**, and writes comparable reports gated by `run/criteria/block_raise.yaml`. This phase delivers:

- **The runner skeleton.**
- **Criteria evaluation.**
- **Report generation:** JSON + a small HTML page.
- **Stage 1:** wraps A3.
- **Stage 2a:** the policy's predictions on held-out demos, mapped to the robot and checked with IK. Shows whether the outputs are feasible and how close they are to the demo.
- **Stage 2b:** the full live stack with the demo video streamed over emulated Wi-Fi, teacher-forced. Shows whether the live wireless pipeline gives the same predictions as offline, and measures timestamp error.

Stage 3 (closed loop) and sweeps come in B9.

## CLI

```
python -m franka_sim eval --deploy-config controlSW/franka_deploy/configs/deploy.yaml --profile sim-iphone-fake \
    --stage 1|2a|2b|all [--policy <run/policy id>] [--episodes N | --demos 0,3] [--set k=v ...] [--seed 0] --out DIR
```

- **Run dir:** `DIR/<stage>_<policy>_<station fingerprint[:8]>_<sha8(sets)>/`, containing `station_resolved.yaml`, `criteria.yaml` (the copy used), `metrics.json`, `report.json`, `report.html` and stage artefacts.
- **`DIR/summary.json` + `summary.html`:** one row per run dir found (policy, profile/sensor, robot, stage, verdict, key gate values).
- **Environment isolation:** the runner itself runs in `$RE` (mujoco). Torch work is a subprocess with `cfg.python.bp` (`predict_demos`). The sim side never imports torch, and the BP side never imports mujoco.

## criteria.py

```python
def evaluate(criteria: dict, metrics: dict, stage: str) -> dict
    # -> {"stage", "criteria_version", "gates": {name: {"value", "threshold", "op", "pass"}}, "verdict": "PASS"|"FAIL"|"INCOMPLETE"}
```

- **Gate names** follow `criteria.<stage>.*` keys. Keys ending `_min` mean value ≥ threshold, `_max` mean ≤, and booleans must be true.
- **Per-protocol thresholds:** dicts like `{v1: 30, v2: 5}` select by `metrics["protocol"]`.
- **Missing metric:** the gate is `INCOMPLETE` (not PASS).
- **Pure:** no I/O.

## report.py

- **`report.json`** (schema `sim_report/v1`): `{schema, stage, policy_id, policy_kind, profile, sensor, robot, station_fingerprint, criteria_version, image_source, seed, started, duration_s, metrics, gates, verdict, notes}`.
- **`report.html`:** self-contained (inline CSS, no external assets), readable in a browser:
  - header (policy, sensor, robot, stage, verdict badge);
  - gates table (value, threshold, pass/fail);
  - a few key per-demo rows;
  - a banner when `image_source == render` ("rendered images: success is not a real-world estimate"). It can't appear in B8, but implement it.
  - If you add any chart, keep it simple inline SVG.
- **Reuse:** `franka_deploy.eval.report.episode_metrics`/`summarize` for session-based stages (2b) where the episode layout matches. Do not modify franka_deploy/eval/report.py (Track A-owned).

## Stage 1 (`eval/stage1.py`)

- Calls `stage1_replay` (library API) for the profile's station, robot and tooling, with `--set` passthrough. The design sweep is not repeated by default: use the station's current tooling values.
- Copies its key metrics into `metrics.json`: n_feasible/45, reachable fraction at the recommended placement, worst joint margin, worst tooling clearance, collisions, clamp fraction, slowdown, mapped width p99 vs stroke.
- Evaluates `criteria.stage1`.

## Stage 2a (`eval/stage2a.py` + `tools/predict_demos.py`)

1. **`predict_demos.py`** (BP subprocess): `python -m franka_deploy.tools.predict_demos --policy <policy yaml resolved> --zarr Z --split val|all --every <exec_h> [--demos ...] [--seed 0] --out pred.npz`.
   - **Policy kinds:**
     - `bp_server` (and any `command` policy): start the policy server process and query it through the **robotmq protocol**, exactly as deployment does, using the deployment obs builder from the dataset. This makes 2a policy-agnostic. Reuse what `tools/offline_eval.py` / `tools/agent_capture.py` / `tools/obs_equivalence.py` already do to build deployment-format observations from zarr frames; read them first.
     - `replay`: actions straight from the demo (`replay_server` convention: `action[k] = inv(P(t))·P(t+3k)`), which gives zero error by construction.
     - `fake`: the identity chunk.
   - **Output:** for each queried frame i of each demo, `rel_chunks (K,10)` (pos3 + rot6d + width), the demo's future relative poses over the same horizon, frame index, episode, inference time.
2. **Stage 2a mapping** (sim side):
   - for each queried frame, the anchor = the demo TCP at frame i in the robot base frame, via the Stage 1 recommended placement for that demo (from a Stage 1 run dir, `--stage1 DIR`, or by running Stage 1 first);
   - absolute chunk poses = anchor·rel_k;
   - `kinematics.check_traj` on the chunk (and on the demo future for reference).
3. **Metrics:**
   - chunk reachable fraction, chunk joint margin min (deg), collisions;
   - position error vs the demo at k = 4, 8 and 15 (p50/p95 mm), rotation error (deg);
   - width error;
   - inference time p50/p95.
4. Gates from `criteria.stage2`.

## Stage 2b (`eval/stage2b.py`)

1. Run the launcher for the profile, forcing `run.sim = video_replay` on the chosen demo, with the policy given:
   - `--no-tty --script "<t0>:c,<t1>:s,<t2>:q"`, durations from the demo length;
   - the task's teacher-forcing history source `--history-source replay_gt --replay-npz <demo npz> --replay-start-now-ns <first_tick_ns from the sender ready file>`. Check what `franka_task.py` supports, and whether the launcher can pass these flags. If the launcher lacks a passthrough, add a minimal `task.extra_args` deploy key in the launcher (Track B owns it).
2. **Treat `sender_died` or a launcher FAIL as `INCOMPLETE`** with the reason recorded.
3. **Post-process the session:**
   - `analyze_tap` contract check;
   - live predictions vs the Stage 2a offline predictions on the **same frame indices** (match by `replay_frame` or the tap's demo index): position error p95 mm at k = 4/8/15;
   - timestamp error from joining `logs/sender_truth.jsonl` with `logs/camera_truth.jsonl` on (seq, stream): p50/p95 ms;
   - frame-selection errors, stale-image count and holds from the task summary;
   - receiver health (fps, age p95, reconnects) from `logs/camera_stats.json`.
4. Gates from `criteria.stage2` (`live_vs_offline_*`, `frame_selection_errors_max`, `cam_stamp_err_ms_p95_max` by protocol).
