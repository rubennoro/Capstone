## Findings
1. **FIX (breaks the live tree):** `model.py:240,268`: `grip_solimp` must be 5 values for the MuJoCo spec. `configs/run/sim/physics.yaml:12` (added concurrently, Track B/coordinator) has 3 (`[0.95,0.99,0.001]`), so `build_model` raises TypeError for every profile that loads physics.yaml. 2. **FIX (flaky test, minor real race):** `hand_server.py:136` computes `grasped` in the reader thread using the mode at read time, so `hand_state` can show `mode=holding, grasped=False` for up to one 10 ms read period. `test_hand_driver.py:102 test_server_topics` failed 2 of 5 isolated runs (and the first full run). Store the raw `is_grasped` and AND it with the current mode inside `state()` (line 104).
3. **FIX/decision (width units, see below):** `width_map.b` is almost certainly wrong, and `home_width_m` is in the wrong units in model.py:494.
4. Grasp-eps fidelity: sim and FakeHand stop closing at `width - eps_inner`. Real libfranka may close onto the object and merely report failure (checklist §7 asks this; keep it open). With eps 0.05 the check `grasp_ok` is nearly vacuous (any gap >= 5 mm).
5. `HandCommandPolicy` ignores `last_result`/`mode`: after `grasp_failed` or a hand_server restart mid-hold it stays GRASPING and never re-grasps (`hand_logic.py:~125`). Acceptable for v1; log it as a hardware-day risk.
6. `LibfrankaHand.close()` (`hand_server.py:114`) calls `stop()` on SIGTERM; with a held eraser this may drop it at shutdown. Document in the checklist.

## Deviation judgments
1. **grip_contact solref/solimp: plausible, not a fudge.** My probe (45 mm box, 30 N, Panda): MuJoCo defaults give 4.6 mm penetration per pad, gap goes to -7 mm (box crushed) and 1.5 mm drop in 2 s; solref 0.01 gives 3.3 mm / 0.18 mm drop; A5 values give 0.13-0.19 mm, 30.00 N, 0.18 mm drop. Soft constraints scale with the 15 g mass, so the default sink is a solver artefact, not a grasp problem. Side effect: eraser-table contact is also stiffened (geom mix); harmless.
2. **Thresholds verified from the zarr** (37,971 frames, 45 episodes): 0.064/0.070 gives exactly one grasp and one release in 45/45; spec 0.060/0.066 gives 44/45 (one episode never triggers). Trigger widths 0.0610-0.0640, in-grasp max 0.0640, min post-release 0.0730. Margins are thin: the closest trigger is 0.02 mm under 0.064; fitted to this dataset, so re-check on real data.
3. **eps_inner 0.01 vs 0.05:** the grasp fires at train width 0.061-0.064 (gap ~0.055) while the eraser stops the pads at gap ~0.012, so eps must be >= ~0.044. The live closed-loop merge used the station's 0.01 (`controller_fragment` overrides the HandPolicyConfig default), which would have failed the grasp in both profiles. The coordinator has since set 0.05 in both tooling yamls; confirmed in the files. Keep the hand_logic default in sync.
4. **HandSim ramp + feed-forward:** sound (trapezoid, vmax 0.1002 vs 0.1117 without; tests assert <= 1.1 v). Lock use is correct (command() and state() under the HandSim lock; ctrl() runs on the loop thread).
5. **hand_server stop() thread:** no race found. The stopper is joined before the next command starts, `_interrupted == _run_id` is checked under the lock, and a stopper is created only when busy. Only the finding 2/6 items remain.
6. **Driver send_failed:** single-slot undo is correct; when `hand_state` is stale the policy is not consulted, so no commands go out to a dead server. Cost: a lost reply with an accepted command re-issues it (duplicate grasp = stop plus re-grasp, brief).

## Width units (open question 3) and home gap (4)
- Scene eraser is 60 x 20 x 12 mm (`block_raise_table.yaml:5`), so the gripped side is 20 mm. Data hold widths are 0.046-0.062 (zarr), and the same tooling yaml records `train_closed_m: 0.0431` (tag separation at gap 0).
- With a=1: `train = gap + b` requires b = 0.0431 at gap 0. **b = 0.008 is the wrong value**; b ~ 0.043 gives hold gaps 0.003-0.019, matching a 20 mm eraser (soft-finger squeeze), and open gaps 0.035-0.041. The coupled bug: model.py:355-358 also uses b as the pad offset (pad separation = gap + b), so only a decoupled `pad_offset_m` (~0.008) lets the 20 mm eraser fit once b = 0.043. A3 width metrics (`stage1_replay.py:495`) cannot discriminate: they pass for either b.
- Sim consequence now: the policy sees `get_width = train(gap)` = 0.020 while holding the eraser (pads at gap 0.012), 25 mm below train_min 0.0447, i.e. out of distribution; with the fix it would read ~0.055-0.063.
- Home gap: `home_width_m` 0.08 comes from `run_task.py:92` (training units) but model.py:494 uses it as a physical gap (key gap 0.08). The controller commands train 0.08 = gap 0.072 (b = 0.008) or 0.037 (b = 0.043), so the first move shifts the fingers. Fix: key gap = `WidthMap.gap(home_width_m)`.
