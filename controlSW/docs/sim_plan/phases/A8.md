# A8: Stage 1b campaign, full-stack demo replay with physics (Track A, wave W9)

## Goal

Replay every firstreal demo through the **whole stack** (launcher → task → bridge → MuJoCoBackend + hand_sim + scene,
render sender on the image side, `policy: demo_replay`) and measure whether the simulated arm tracks the demo. Stage 1
(A3) answered "is each demo kinematically feasible with this tooling"; Stage 1b answers "does the controller + hand +
scene reproduce it without faults". This is the last Track A phase before the W10 system review.

## Behaviour

`python -m franka_sim campaign --stage1 stage1.json --config deploy.yaml --profile sim-iphone --demos all|0,3,7 --speed 0.5,1.0 --out DIR [--jobs N] [--set k=v ...]`

Per demo d × speed s:
1. Overlay (via `--set` / a session overlay, never by editing repo YAMLs): `q_init = q_start[d]`; object at demo d's
   grasp location; hand gap = gap(w0); home = start TCP; replay episode d at speed s.
2. Run `franka_deploy run --no-tty --script "3:c,<T>:y,<T+3>:q"` with T from the episode length / s. Ports from
   `FD_TEST_PORT_OFFSET` (Track A = 1000) so the campaign can coexist with Track B tests; with `--jobs N` give each job
   its own offset.
3. Collect per run: `sim_gt` (A6 `ground_truth.evaluate_episode`), TCP path vs the demo after time alignment (fraction
   of samples within track_pos_m / track_rot_deg over a sliding 5 s window → `track_ok`), clamp count, settle timeouts,
   reflexes (count + which), hand statistics, peak F_ext, `pad_table` contacts **reported separately** from reflexes
   (A6 finding 5), system faults (launcher/sender/bridge died, timeouts) as their own class.
4. Demos infeasible in stage1.json are run but labelled `stage1_infeasible`, excluded from the tracking denominator,
   and listed.

Output `DIR/campaign.json` (schema `sim_campaign/v1`): config fingerprint, per-run rows, aggregates per speed with
Wilson 95 % CIs, and the session dirs. Also a short `campaign.txt` table. Resumable: a rerun skips rows whose session
already has a final row (same fingerprint).

Criteria values come from `criteria.stage1b`; nothing hardcoded. v_max stays the station/criteria value (≤ 0.25).

## Tests (`MUJOCO_GL=egl`, RE, Track A port offset)

- Unit: alignment + window metric on synthetic paths (perfect track → 1.0; 2 cm constant offset → 0.0; a single
  spike shorter than the window does not fail a run); Wilson aggregation; resume skip; infeasible labelling; overlay
  construction (q_init / object pose / gap from a fixture stage1.json).
- Process (lock-wrapped, background): 2 demos × speed 0.5 on `sim-iphone`, end to end, sessions pass
  `franka_deploy validate` and `eval`.
- Campaign run (lock-wrapped, background, outputs in scratch `$S/a8/`): **all 45 demos at speed 0.5 on `sim-iphone`,
  Panda, recommended tooling (+10 cm / −y)**. The tooling YAMLs still say `extension_m: 0.0` (placeholder, user decision
  pending): apply +10 cm as a run override (`--set tooling.finger_adapter.extension_m=0.10`; camera side −y is already
  the YAML value), never by editing the YAML, and record the override in campaign.json. Then the same at speed 1.0, and
  one stock-length (extension 0.0) speed-0.5 run for comparison, if time allows. Copy only `campaign.json` + `campaign.txt` into
  `controlSW/docs/sim_plan/results/stage1b/`.

## Acceptance checklist

1. All 45 demos at speed 0.5 run with **0 system faults**.
2. Tracking metric holds on ≥ 90 % of the feasible runs (Wilson CI reported). If it does not, that is a finding, not a
   reason to loosen the criteria: report the failing demos and the cause class (reflex, pad_table, overshoot, hand).
3. Sampled sessions (≥ 3) pass `franka_deploy validate` and `eval`.
4. The franka_sim suite and the RE franka_deploy suite pass; regression guard (`check_protected.sh`,
   `test_iphone_deploy_unchanged.py`) passes.
5. Ownership: Track A files only (+ the stage1b.yaml note above); I-CAMPAIGN appended to INTERFACES.md.
