## Findings
1. **FIX (Track B + configs): the controller TCP is not the model TCP.** `station.py:336` copies `tooling.F_T_TCP` verbatim, `launcher.py:406` builds home and q_init from it, and both tooling YAMLs (`:25`) hold `C_T_TCP` + 0.1 m z.
   - The placeholder is not even self-consistent: Fst·inv(C_T_TCP) = a pure +100 mm z shift, which puts the camera on the flange axis inside the hand. It does not depend on `extension_m` or `tcp_x_along_hand`.
   - Fix: for `run_mode == sim`, while `tooling.F_T_TCP` is a placeholder, `build_controller_cfg` takes F_T_TCP from finding 2. It records `F_T_TCP_source: model` in station_resolved and the report, and `station_home` follows automatically.
   - Also: add a preflight that refuses a sim run when controller and model F_T_TCP differ by more than 1 mm / 0.1 deg (this catches a stale `--set`).
2. **FIX (Track A): expose the derived TCP as a function and guard it.**
   - Add `franka_sim.model.derived_tcp(station) -> {F_T_TCP, EE_T_TCP, F_T_C_main, fingerprint}`, using `build_model(..., with_scene=False)` or a cached hand-only compile. Finding 1 calls it.
   - `MuJoCoBackend.from_config` already has the station: print a loud WARNING when the station F_T_TCP differs from `sm.F_T_TCP` (`info.station_F_T_TCP_deviation`).
   - After that, drop the hand-made override in `campaign.py:717-738`, or keep it only as an assertion.
3. **LOW (Track A): `F_T_C_main` is ignored.** `model.py:451` always derives the camera from F_T_TCP. Once hardware gives a measured F_T_C_main (from fdcal handeye), the model should use it, with F_T_TCP = F_T_C_main·C_T_TCP. Otherwise the YAML comment at `:27` ("null -> derived") has no non-null branch.
   - Related: with `use_station_F_T_TCP` true and a measured F_T_TCP, the `tcp` site and the cameras move but the pads do not. `scene.grasp_tcp_height_m` and the "TCP = pad centre" docs then no longer hold. Document this, or report the pad-to-TCP offset in `info`.
4. **LOW (Track A, CAD input): the TCP-relative tag puts the tag off the printed finger.**
   - With `TAG_Z_FROM_PAD_M` -0.108 (`model.py:412`), at ext 0.10 the tag centre sits 89.3 mm from the flange. That is on the *stock* finger, 23 mm before its tip at 112.3 mm, not on the adapter (112.3-212.3 mm).
   - At ext 0.0 it sits at -10.7 mm, behind the flange and inside link 7 (tag_probe, all 4 arm/side combos at ext 0.0).
   - So camera-check results at ext 0.0 are not physical. The printed part must carry the tags 108 mm above the pad centre (a sleeve over the stock finger), or the extension must grow.
   - Add `info["tag_on_adapter"]` and a warning. The tag/camera/TCP invariants themselves are right.
5. **LOW (configs = Track B; A8 known item, now concrete): `tcp_x_along_hand` semantics.**
   - TCP y = z × x, so the camera (TCP -y) sits on hand **+x** for `+y` and on hand **-x** for `-y`. In flange coordinates that is (+82.7, -82.7) and (-82.7, +82.7) mm.
   - Suggested YAML comment: `TCP x = sgn·hand y; camera on hand sgn·x (+y: hand +x side, -y: hand -x side)`. Rename Stage 1's `camera_side` label (Track A, `stage1_replay.py:740`) to `tcp_x_along_hand`.
   - The YAML still says `"+y"`, while Stage 1 recommends `-y`.
6. **LOW (Track A): loop statistics under-report stalls.**
   - On resync, `backend.py:220` zeroes `behind` before `:258` records `_lag_max`, so the stall that caused the resync is never in `sim_lag_ms_max`. Under 20-process load: max wake period 70-81 ms, but `sim_lag_ms_max` only 19-27 ms.
   - `rt_resyncs` (`:449`) is cumulative while every other stat is per window. Record the lag before the reset, and report resyncs per window.
   - Loop health itself is fine. Idle: p99 1.16 / 1.64 ms, max 4.6 ms. Loaded: p99 1.05-1.39 ms, p999 2.2-7.7 ms, 1-2 resyncs. RTF 1.0, 1505 PUB in 15 s (100 Hz), no reflex, and only MainThread left after `close()`. The A8 figure (jobs 3, p99 10-15 ms) is whole-stack contention, not a loop defect.
7. **LOW (Track A): shm leak after SIGKILL.** On the SIGKILL path (`campaign.py:864`) the launcher's `cleanup_shm` never runs, and `--launch-child` tolerates foreign segments, so leaks can pile up unseen. After a kill, glob-remove `rmq_*_<child pid>_*`. `/dev/shm` is empty now. Renderer EGL cleanup is explicit everywhere (`camera_check.py:470-476`, render_sender `close`).
8. **INFO: reset / state / GT timing and determinism are OK.**
   - `sim_reset` runs under `_core_lock`, zeroes the eraser qvel, restores on penetration, and rebuilds state from a fresh `mj_forward`. The state dict is built in the 1 kHz wake on a wall-clock cadence, and its `t_mono` matches `get_state`.
   - Determinism: the physics is deterministic, but the wall-clock coupling makes target timing vary from run to run. A8 measured ≤ 0.3 mm p50, and the model fingerprint is stable. Accept this and document it.
9. **INFO (cross-phase, A3 caveat B restated):** Stage 1 "feasible 43/45" does not apply the bridge's 60 deg EE cone, while Stage 1b's 28 safety_clamp rows are mostly that cone. With the derived TCP the cone is the TCP tilt (TCP z = flange z), so changing the TCP does not change this. It is a user decision (scene yaml `cone_max_deg`).

- **The sim has one source:** the model-derived F_T_TCP, a function of the hand MJCF, `extension_m`, `pad_size_m` and `tcp_x_along_hand`. Expose it through `derived_tcp()` (Track A) and let the launcher use it for every sim run while the YAML value is a placeholder (Track B).
  - Set both tooling YAMLs' `F_T_TCP` to `null`, provenance "derived: franka_sim model". Do not commit a numeric copy: it goes stale under every `--set` of extension or side.
- **Hardware:** fdcal handeye produces F_T_C_main; then F_T_TCP = F_T_C_main·C_T_TCP (status measured). The model consumes it (finding 3).
  - The CAD target for the mount is the sim-derived F_T_C_main. For ext 0.10 / -y: (-82.7, +82.7, 9.8) mm, i.e. derived F_T_TCP·inv(C_T_TCP).
- C_T_TCP stays the training-defined invariant that fixes camera to TCP. Extension and side only move the camera and tag assembly relative to the hand.
