# B3: policy slot + policy contract tool (Track B, wave W3)

## Goal

Make "which policy" a plug-in. The launcher starts any policy kind from `run/policy/<id>.yaml`. A contract tool proves that a server speaks the protocol the task expects. A short doc tells a teammate how to add a new policy, e.g. a plain diffusion policy.

## Changes

1. **`mocks/fake_policy_server.py`** (additive):
   - `--ready-file F` writes JSON `{endpoint, pid, ready_monotonic, kind: "fake"}` atomically, as `inference/server.py` does;
   - `--k 16` (number of steps) and `--reset-delay 0.0`, so tests can build deliberately broken servers;
   - `--no-prompt-rules` (`use_prompting: false` in the config and no prompt enforcement), to mimic a plain diffusion policy.
   - Defaults stay unchanged.
2. **`launch/launcher.py`:** `start_policy(policy_cfg)`, dispatching on `kind`:
   - `bp_server`: today's `inference.server` command;
   - `replay`: today's `replay_server` command (`--replay-episode` still works and maps to it);
   - `fake`: `fake_policy_server --ready-file --delay`;
   - `command`: a template list with `{python}`, `{endpoint}`, `{ready_file}`, `{work_dir}`, `{checkpoint}` placeholders; `python` resolves to `cfg.python[<name>]`.
   - Resolution: with a station `run.policy`, use it; otherwise today's `checkpoint`/`prompt_zarr` keys mean `bp_server` (identical command, so the golden still holds).
   - The ready-file wait and timeout come from the policy `ready_timeout_s`.
   - `check_config` validates the policy (kind known; `command` has `{endpoint}` and `{ready_file}`; checkpoint exists for `bp_server`).
3. **`tools/policy_contract.py`:** `python -m franka_deploy policy-contract --endpoint E [--prompt-index 0] [--task-name block_raise] [--obs dummy|tap:DIR] [--expect run/policy/<id>.yaml] [--out contract.json]`. Steps:
   1. `policy_config` has keys `workspace.{proprio_length,img_obs_horizon,obs_down_sample_steps,ultrawide_down_sample_steps}` and `use_prompting`;
   2. `policy_reset` answers in under `reset_max_s` (default 0.5 s), measured 5×, max reported;
   3. when `use_prompting`, inference before a prompt returns an `ERROR…` string;
   4. a prompt with the SafePolicyAgent payload `{task_name, prompt_index}` returns OK;
   5. a second prompt without a reset returns ERROR (when prompting);
   6. inference with a `CONTRACT_OBS`-shaped dummy obs (or real obs from a tap directory): every `CONTRACT_REPLY` key, K = `contract.K` (16), finite, rot6d rows with norm in [0.9, 1.1] and near-orthogonal (|dot| < 0.1), width in [0, 0.12], and action 0 within 2 cm / 5° of identity (warning only);
   7. the `export_recorded_data` topic answers (a missing topic is a warning).
   - Import `CONTRACT_OBS`/`CONTRACT_REPLY` from `analyze_tap`; never copy them. The client must use per-topic timeouts and no resend (like `SafePolicyAgent` / `NoResendClient`).
   - Output: a pass/fail table on stdout and the JSON. Exit 0 or 1.
   - `__main__.py` passthrough: `policy-contract`.
4. **`controlSW/docs/adding_a_policy.md`:**
   - the 5 topics with request/reply payloads, shapes and dtypes, timing limits (reset < 0.5 s, inference < `inference_timeout_s`);
   - the pose convention (relative to the last observed pose, rot6d = first two rows, absolute width in training units, K = 16 at 50 ms);
   - how prompting is ignored by a non-prompting policy;
   - how to write `run/policy/<id>.yaml` (`kind: command`, with an example for a UMI diffusion-policy server);
   - how to run the contract tool and a sim eval with it.
