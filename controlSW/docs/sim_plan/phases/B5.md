# B5: WirelessCamera receiver + ClockMap (Track B, wave W5)

## Goal

The policy-host half of the wireless sensor path. A real-env `BaseCamera` subclass:
- receives frames over Socket.IO from the iPhone app (v1) or from the rig/sim senders (v2);
- maps each frame to a capture time on **this host's** `time.monotonic()` clock, exactly once;
- republishes at a fixed 60 Hz (so `fps % 20 == 0` holds);
- refuses to publish stale frames;
- reports health.

Downstream, the task reads it through robotmq shared memory exactly as it reads RigCamera today.

## ClockMap (`clock_map.py`)

```python
class ClockMap:
    def __init__(self, mode: str, latency_s: dict, *, fps_hz: float | None = None, window_s: float = 2.0,
                 residual_s: dict | None = None)
    def map(self, stream: str, t_arrival: float, t_sender_ns: int | None = None, seq: int | None = None) -> float
    def add_ping(self, t0_ns: int, t1_ns: int, t2_ns: int, t3_ns: int) -> None    # v2 clock sync samples (host t0,t3)
    def stats(self) -> dict      # mode, offset_s, rtt_ms_min, drift_ppm, n_pings, monotonic_clamps
```

Modes:
- **`arrival_minus_latency`:** `t = t_arrival − latency[stream]`.
- **`arrival_dejitter`:** a lower-envelope fit of arrival times on the nominal frame grid `a + k/fps`.
  - k is assigned by rounding, so frames dropped on the phone side leave gaps.
  - The envelope is the minimum residual over `window_s`, refit as samples arrive; it absorbs network jitter but not true latency.
  - `t = envelope(k) − latency[stream]`.
- **`sender_stamp_ping`:**
  - offset θ from the min-RTT ping in the window, θ = ((t1−t0)+(t2−t3))/2 (sender − host);
  - linear drift by least squares over the min-RTT samples per sub-window;
  - `t = t_sender − θ(t) − residual[stream]`.
- **`sender_stamp_realtime`:** the sender stamps CLOCK_REALTIME and both hosts run chrony: `t = t_sender_rt − (time.time_ns() − time.monotonic_ns())·1e-9 − residual`.

The output is clamped so each stream is non-decreasing (count the clamps).

## WirelessCamera (`wireless_camera.py`)

```python
class WirelessCamera(BaseCamera):
    def __init__(self, transport: dict, clock: dict, health: dict, publish: dict | None = None, stats_path: str | None = None,
                 truth_path: str | None = None, on_size_mismatch: str = "error", **base_kwargs)
    def get_images_bgr_hwc_and_timestamp(self) -> tuple[dict, float]
def main(argv=None)   # python -m franka_deploy.peripherals.wireless_camera --config camera.yaml
```

- **`base_kwargs`** go to `BaseCamera` with `camera_latency_s = 0.0`; ClockMap applies the latency exactly once. Assert or force this.
- **Servers:**
  - one Flask-SocketIO app per configured port, `async_mode="threading"`, websocket required, in daemon threads, bound to `transport.bind_host`;
  - v1 handlers: `rgb` (str base64 JPEG, decoded with cv2.imdecode to BGR), `validate` (returns `transport.validate_ack`, which must be non-empty), `depth` (counted, ignored);
  - v2 handlers: `hello` (logged, checked against the sensor yaml: protocol, size, fps, K within 1e-3), `packet` (binary JPEGs, stamps, seq);
  - for v2, a background thread calls `clock_ping` at `clock.ping_hz` and feeds ClockMap;
  - record the engineio transport on connect and upgrade; count connects, disconnects and reconnects per stream.
- **Frame store:** the newest frame per stream, as `(bgr, t_capture_mapped, t_arrival, seq)`, under a lock. Decoding happens in the socket thread.
- **Fixed-rate publish** in `get_images_bgr_hwc_and_timestamp`:
  - sleep to the next tick of `camera_configs.main.fps` (60);
  - return `{"main": bgr_main, "ultrawide": bgr_uw}` and the **main frame's mapped capture time**;
  - a repeated frame keeps the same timestamp, as RigCamera fixed_rate does;
  - before both streams have a frame, or when `time.monotonic() − t_main > health.max_age_s`, return `({}, 0.0)` and count `stale_ticks`. BaseCamera skips publishing on an empty dict: verify that in base_camera.py.
- **Size mismatch:** if a decoded frame isn't `camera_configs[stream].width×height`, raise a clear error ("iPhone app is on Low (320x240): set Stream resolution = High"), or count it when `on_size_mismatch: count`.
- **Health:**
  - every `stats_period_s`, atomically replace `stats_path` JSON and log one line;
  - per stream: `fps_in`, inter-arrival p50/p95/max, `age_s` p50/p95, decode ms p95, connects, reconnects, transport, size mismatches, seq gaps (v2), skew main↔uw;
  - global: `publish_fps`, `stale_ticks`, ClockMap stats.
- **Truth log** (sim only, `truth_path`): append `{seq, stream, t_est, t_arrival}` JSON lines. Tests join it with the sender truth file on (seq, stream).
- **GIL measurement:** robotmq calls may hold the GIL. Add a test that measures the inter-arrival jitter the receiver adds: sender-side send times vs receiver-side arrival times on `ideal`, at 2×960×720 at 30 fps, with BaseCamera publishing. Report p95. If the added p95 is > 5 ms, document it, and implement the split design only if trivial; otherwise report it as an open item for the orchestrator.
