## Findings
1. **Real-policy 2b gap (live vs offline p95 10.8 mm iPhone, 29.8 mm rig vs 5 mm gate): expected, not a pipeline defect.** Tests on the iPhone
   session (bp_run001, demo 0, 25 calls), all offline, same checkpoint and noise seeds:
   - offline re-run vs recorded offline: 0.0 mm. The seeds match and inference is deterministic (deviation 4 confirmed).
   - shifting every query by +1 frame (16 ms): p50 1.0 / p95 2.2 mm at k15; -1 frame: p50 1.0 / p95 13.6 (one outlier); +0.5 frame: p95 1.5 mm.
     So timestamp error cannot be the main term (the stamp p95 is 12 ms, deviation 1).
   - older UW frame (-1 UW index): p95 12.6 mm; JPEG q90 on the 224 px zarr images alone: **p50 5.5 / p95 19.7 mm** at k15.
   - Live vs offline measured: p50 3.8 / p95 10.8 mm. The same size as a JPEG-level image change.
   Dominant cause: the diffusion policy's sensitivity to small image differences (JPEG, resize/crop path vs the zarr 224 images, UW frame choice),
   amplified by small n (25 and 11 calls; a p95 of 11 samples is the max). The 5 mm p95 gate is not reachable by any wireless-JPEG stack.
   **Recommend the gate change, not the pipeline:** gate p50 <= 5 mm and p95 <= 25 mm at k15 (or reference the JPEG-perturbed offline noise floor), and
   require n_pairs >= 50 (more demos or a longer clip). Add what the stage cannot see today: pass `--zarr` to analyze_tap with `tap_images_every>0`
   (it already computes `image_mae_224_main_vs_zarr` and `uw_frame_offset_vs_training`) so image divergence is reported next to the action gap.
   Criteria values are the orchestrator's/user's decision (run/criteria/block_raise.yaml, `status: decision`).
2. **Deviation 6 (t_c = 12 s for server policies): evaluates a random slice of the demo.** The first call landed at demo frame 842 (of 996)
   with `start_frame` 838, so `wrt_start` is identity at the end of the demo: out of distribution (training: episode start). Live and offline share it, so the
   comparison stays valid, but the 2b numbers are not representative. Fix: set `--replay-start-now-ns` at the 'c' time (script t_c) so the first
   call sees frame ~0. stage2b.py:187-188, launcher.py task_replay_args.
3. **Deviation 1 (link latency raised to clock.latency_s = 80 ms) is a sound model, and hides no bug the sim could find.** v1 has no stamps, so the receiver
   subtracts a constant; the sim sender has no capture pipeline. With the default 8 ms link the error is -72 ms (4 frames). Residual stamp error 5.4 ms
   median / 11.7 ms p95 is then Wi-Fi jitter only. It cannot validate the 80 ms constant (hardware day must measure it). Side effect: receiver_age p95 is 109 ms,
   so the Stage 3 gate `receiver_age_s_p95_max 0.15` has 40 ms left. B9 should move the capture latency into the sender (not `link.latency_s`) and
   set it only where the real app has it. stage2b.py:86-92. Note: the per-demo duplicate note (R.notes appended per demo).
4. **franka_task.py replay_gt change: safe.** All hunks (franka_task.py:96, 345, 510-516) are inside `history_source == "replay_gt"` or reset the new
   `_replay_start`; commanded/measured paths unchanged; check_protected + iPhone unchanged tests PASS. The start pose = demo pose at the oldest obs of
   the first call, the same rule as `policy_start_eef_xyz_wxyz` (:414-417). Not iPhone upstream, so additive-only/subclass rule does not apply.
5. **Stage 2a margin value is a solver floor.** `check_chunks` re-solves weak frames at the criterion margin and `max(mm, margin_req)` within 1e-6
   (stage2a.py:97-111), so the gate value reads exactly 10.0 (rig) when any frame needed the re-solve (earlier 1.1 deg was check_traj's 0.02 rad limit).
   Valid (same solver as Stage 1), but the reported number is not a measured minimum; add a note/metric `n_resolved_frames`.

   correct. Caveat: `build_replay_npz` swallows any exception and silently falls back to a uniform 60 Hz grid, and `time_source` is not reported (stage2b.py:60-67); surface it in notes.
   The `demo_replay` 2b PASS uses `reply_replay_frame` (stage2b.py:211), so it does not exercise the time-to-frame mapping; only a real policy does.
