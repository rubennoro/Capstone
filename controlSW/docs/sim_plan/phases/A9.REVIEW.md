## Findings
1. **(major, D1/A9c) Kit masses never reach the dynamics.** model.py:462/487 sets geom masses on the menagerie finger bodies.
   Those bodies carry an explicit `<inertial mass=0.015>` (hand.xml:67) and the compiler uses inertiafromgeom auto, so the
   geom masses are ignored. body_mass stays 0.015 in every mode, even with 2 x 77 g placeholder adapters. model.py:851
   ("kit parts are in the finger bodies") and finger_model.md:139-140 ("1b, 3 (inertia)") and :35 are therefore wrong.
   Fix: add the kit/adapter mass and inertia to the finger body (explicit inertial), or document it as not simulated.
2. **(major, D3) camera-check pairs the sim tags with the detected ids by image u-order** (camera_check.py:718), not by the
   kit tag `id`. model.py `_mount_kit` doesn't record which id sits on tag_l/tag_r. A swapped holder/camera_face would pass
   silently, against the plan's "a left/right swap shows up as a failed check". Fix before P1: put the per-finger tag ids in
   `info["finger_kit"]` and use them in camera-check (keep u-order for box mode).
3. (G1, resolved) `tooling_mass_kg` 0.299 = housing 0.199 + cradle_back_plate 0.10 (rig 0.25 + 0.10). It is the phone mount only and is
   identical at 3bfadbf. Correct, but the report label (finger_kit_cli.py:327) should say "phone mount (housing + cradle)".
4. (minor, D2, G2) The stock `friction` is blank (finger_kit_cli.py:311). The compiled value is [1, 0.005, 0.0001]: read
   `geom_friction[pad_l]`.
5. (minor, D3/A9c, G4) Stock flange_to_tip 0.1114 m is pad_1's top (finger z 53.0 + 58.4). The stock mesh tip is 0.1123 m
   (`_finger_tip_z` 53.90, finger_1). The 0.9 mm gap is a label/convention issue, not a bug: say "pad top" in the report/doc.
6. (minor, D3) camera_check.py:317: the "has no tags" mapping is dead code since D1 (model.py no longer raises it). The
   post-build `tag_guard` covers finger_only. In stock mode the summary column reads `tooling.finger_adapter.None` (stage1_replay.py:934).
7. (minor, D4) finger_model.md:
   - :101/:238 cite `results/stage1b/campaign.txt`; the file is `controlSW/docs/sim_plan/results/stage1b/campaign.txt`.
     Its numbers (0.1973, 3/43, 36/45) are right.
   - :146 says the timestep is 0.002 s; the built sim-iphone model uses 0.001 (physics/render config, consistent with :141).
   - :127/:202 cite `test_model_kit.py:444`; the stock TCP test is :506.
   - :122/:88: 53.86 mm is finger_0's max; `_finger_tip_z` returns 53.90 (all finger meshes). Box TCP is computed from 53.90.
   - :426-428 open items: resolved by 3/4 above.
   - Everything else in sections 4/5/8 matches code, WORKLOGs or my regenerated reports: J, stock pad 17x8x17 @ (0, 5.5,
     44.5), 0.1029, 0.0973, 86.4/78.4 mm, 0.0885, C_T_TCP, holdout px, solref/solimp, eraser, width map.
8. (G3, pre-existing) The −y housing/cradle contacts at home are with menagerie link5/link6 collision meshes (unnamed:
   `link5:geom32`, `link6:geom50`). At 3bfadbf: box ext 0 −y −48..−53 mm, ext 0.05 −0.5..−9.6 mm, ext 0.10 none. They
   come from the phone being placed from a short-finger TCP. Stage 1 counts them as collisions (that is the measurement).
