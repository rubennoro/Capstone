## Findings
1. **FIX (real-arm path)** `backends.py:_errors_text/derive_panda_error:184-212`, `get_state:262`. `last_motion_errors` is latched as an error whenever non-empty, even when no controller is running. libfranka keeps `last_motion_errors` after `automaticErrorRecovery` until the next motion starts. So on hardware `recover()` clears `self.error`, the next `get_state` re-derives it from the stale field, and `start()` (refuses while `error`) can never run: deadlock; the same at bridge boot after a past reflex. The fake test hides it because `_FakePanda.recover` clears `last` (test_sim_backend_stack.py:266). Fix: consider `last_motion_errors` only while `_ctrl_running` (or remember its text at `recover()`/init and ignore an unchanged value until the next `start()`); `current_errors` and `robot_mode == Reflex` stay unconditional. Make the fake keep `last` after `recover()` and add the regression test. Healthy path, latch, 0.5 s grace, start refusal and the bridge callers (`_activate:77`, `tick`, `recover`) are otherwise fine.
2. **FIX (FR3 fidelity)** `simcore.py:168-169` uses the MJCF joint range only; the FR3 MJCF is wider than the station datasheet (q_lo FR3 -2.901/-1.836/.../0.440/-3.051 vs yaml -2.744/-1.784/.../0.545/-3.016). `kinematics.py` (model.py:604-605) uses the intersection. The sim FR3 therefore accepts poses the real FR3 (and Stage 1) rejects. Use `max(q_min_rad, mjcf_lo)`, `min(q_max_rad, mjcf_hi)`. Panda is identical either way. Add a limits assertion to the test.
3. **LOW** `backend.py:204-219` `move_joints` reads `get_state()["mode"]` 2 ms after `begin_joint_move`, but nothing re-snapshots after the lock section (`stop()` does). If the loop thread has not published yet, the cached mode is still the old one and the wait exits at once, then `start()` raises "joint move in progress". Call `self._snapshot()` (or read `self.core.mode` under `_core_lock`) before the loop. `_snapshot` from caller threads (`start/stop/recover`) also reads SimCore without `_core_lock`: a torn read lives at most 1 ms; fine, but note it.
4. **LOW** `test_backend_rt.py:65` asserts `rt_resyncs == 0`; the spec says report it on a loaded machine. It is a flake risk in the wave gate with parallel agents (load was 9-11 during my run, it still passed). Suggest: assert `<= 1` or skip-with-print when `os.getloadavg()[0] > cores/2`.

B8's `from franka_sim.eval import cli` runs unconditionally in `main()`; committing the file without `franka_sim/eval/**` breaks `python -m franka_sim`.
